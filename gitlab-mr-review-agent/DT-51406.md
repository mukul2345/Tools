## Description
Summary
As a QA/dev engineer, I need to run a full end-to-end pass across every MOHRE/MOHESR
integration API built under Epic DT-41849, so we can confirm the complete client journey —
from case submission through insufficiency, status inquiry, work-permit notification, and
the post-ReportQC audit approval flow — works correctly against the legacy Veriflow contract
before the MOHESR client launch.
Epic: DT-41849 (Integration with MOHRE/MOHESR pipeline)
Scope — Features / APIs under test
All endpoints exposed by MohreController (legacy Veriflow contract) plus their
downstream flows:
Authentication
POST /mohre/token — bearer token generation (valid/invalid/missing credentials)

Token validation + authorizeMohreClient middleware on every protected route


Case Submission
POST /mohre/newApplication — user/applicant creation, component + claim item +
verification request creation, master-data lookup translation, duplicate/idempotency
handling via ExternalReference

SQS + GetDocuments document-fetch flow (documents attached to components)


Insufficiency
Outbound insufficiency notification webhook (caseDetail / validation stage)

POST /mohre/insufficiencyFulfillment — validate, resolve, persist, finalize
(including LOA branch)


Case Update / Notification
Document Validation Complete notification (case → verification stage)


Case Status & Inquiry
POST /mohre/issueCertificateByEID — lookup by moheId → emiratesId → unitedIdNumber

POST /mohre/issueCertificateByPassportNo — lookup by passport + nationality + DOB


Work-Permit Notification
POST /mohre/WorkPermitNotification (+ NotificationRequestForWorkPermitProcessStarting
alias) — approve/reject decision, idempotent replay, conflict handling


Report & Audit Handshake
Audit Report API — verification report data sent to MOHESR auditor
(titleCasing, allowed chars, <2MB, office-mapping check)

POST /mohre/notifyToDataFlow — report approval/rejection feedback within the
decision window

Post-ReportQC audit workflow (approval/rejection handling)


Test Approach
Run each API against the target environment (staging/preprod) using the
Postman workspace.

Cover happy path, validation failures, auth failures (401), not-found (404),
conflict (409), and idempotent replays for each endpoint.

Verify legacy Veriflow response/error envelope shape (no DFGResponse wrapper leaks).

Validate the full case lifecycle end-to-end: submission → document fetch →
validation/insufficiency → verification → ReportQC → audit approval → status inquiry.

Confirm MOHESR office-mapping and titleCasing/size constraints on outbound audit data.

Acceptance Criteria
[ ] Every endpoint listed in Scope is exercised for happy path + key error paths.

[ ] Token/auth middleware correctly rejects invalid/missing tokens and non-MOHRE clients.

[ ] A full case lifecycle completes end-to-end and reaches a terminal state.

[ ] Insufficiency raise → notify → fulfillment round-trip works (incl. LOA branch).

[ ] Work-permit notification handles approve, reject, replay, and conflict correctly.

[ ] Report approval feedback + post-ReportQC audit flow behave as designed.

[ ] All responses match the legacy Veriflow contract (shape + status codes).

[ ] Defects found are logged as linked bugs against the relevant story.

[ ] E2E execution results documented (Postman run / test report attached).
